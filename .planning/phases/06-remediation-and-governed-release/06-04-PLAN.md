## On TDD in a test-only plan

There is no implementation to drive here — these guards assert state that already holds, so they pass on first run. The red-green cycle is replaced by an explicit detection proof: for each new test, make one deliberate local perturbation of the thing under guard, observe the test fail, quote the failure line into the task receipt, then revert the perturbation with `git checkout --` before staging anything. A guard never shown to fail is indistinguishable from a guard that cannot fail. The perturbation is never committed.
