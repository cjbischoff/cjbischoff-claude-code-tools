# Plan 16-01: Dependency-Sink Catalog & CWE Mapping

## Goal

Fix the three data/logic defects (D-1, D-2, D-3) that cause the sec-overlay
harness to miss code-injection findings at the earliest pipeline stage.

## Context

CONTEXT.md at `.planning/phases/16-dependency-sink-catalog-cwe-mapping/16-CONTEXT.md`
defect report at `.planning/reports/2026-09-02-sec-overlay-missed-rce-coverage-defect-report.md`

## Task Chain

### Task 1 — Map CWE-94/95 to injection class (D-1)

**Files:** `clsmap.py`

**Change:**
- Add `"94": "injection"` and `"95": "injection"` to `CWE_CLS` dict in `clsmap.py`
- Add eval-related rule-id substrings to `_RULE_ID_CLS`: `eval`, `code-string-concat`
  so `detect-eval-with-expression` and `code-string-concat` semgrep rules resolve
  deterministically

**Acceptance:**
1. A semgrep result with `{"cwe": ["CWE-95: ..."]}` and
   `check_id = "detect-eval-with-expression"` resolves to `injection` class
2. `injection` appears in `canonical_classes()` and is routable through
   `reconcile_plan`

**Verification:** `uv run python -m pytest tests/test_clsmap.py -x -q`

### Task 2 — Abstract npm catalog entries with match-any strategy (D-3)

**Files:** `dependency-sinks.json`, `dependency_sinks.py`

**Change:**
- Add two npm categories to `dependency-sinks.json`:
  - `npm-template-injection` → `cls: ssti`, strategy `match-any`, manifests `package.json`/`package-lock.json`
  - `npm-code-evaluation` → `cls: injection`, strategy `match-any`, manifests `package.json`/`package-lock.json`
- Add `match-any` strategy support to `dependency_sinks.py`:
  - When strategy is `match-any`, the entry matches when ANY dependency is present in
    the manifest (not a specific package name)
  - The indicator list guides the investigate agent but does not gate routing
- Add `package.json` and `package-lock.json` to manifest filename matchers in
  `_manifest_files` / `_SOURCE_SUFFIXES`

**Acceptance:**
1. `reconcile_plan(ws, ["xss"], target_root=<comply>)` returns a list containing a
   template-injection class, on the strength of `package.json:127` alone
2. npm target scanned with npm catalog entries present reports coverage metric

**Verification:** `uv run python -m pytest tests/test_dependency_sinks.py -x -q`

### Task 3 — Fix security_only filter (D-2)

**Files:** `prefilter.py`

**Change:**
- Modify the `security_only` filter in `run_prefilter` to check semgrep result
  metadata before dropping:
  - If result declares `metadata.category: "security"` → KEEP
  - If result declares any `cwe` field → KEEP
  - If neither, check if ruleset is under `lang/security/` → KEEP
  - Only drop results that fail all three checks
- Route unmapped-but-security-declared hits to `security-other` class instead of
  dropping them (modify `cls_from_semgrep_meta` or prefilter logic)
- Create drop ledger at `kb/drop-ledger.json`:
  - Record every `security_only` drop with: `rule_id`, `file`, `line`, `cwe` (if any),
    `metadata.category`, `reason`
  - Append-only array, one entry per dropped finding
  - Count summary at the top

**Acceptance:**
1. CWE-95 `new Function` semgrep hit survives prefilter with class `injection`
   (requires Task 1 to be done first)
2. CWE-declaring semgrep result with unmapped CWE routes to `security-other`
3. Dropped findings appear in `kb/drop-ledger.json` with all required fields
4. Bare-integer `dropped_nonsecurity` still reports the count (backwards compat)

**Verification:** `uv run python -m pytest tests/test_prefilter.py -x -q`
