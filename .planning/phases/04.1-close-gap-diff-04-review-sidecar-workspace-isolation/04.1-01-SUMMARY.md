# Phase 04.1 Plan 01: Review Sidecar Workspace Isolation Summary

**`run_review` now resolves its workspace through `RepoMemory.for_target`, closing DIFF-04's information-disclosure gap where review artifacts leaked at the bare `--root` instead of the git-ignored per-repo sidecar `scan` and `audit` already use.**

## Accomplishments
- `cli.py`'s `run_review` threads `r = runner or subprocess.run` into `RepoMemory.for_target(root, runner=r)`, replacing the direct `Workspace(args.root)` construction — the same sidecar resolution `scan`/`audit` already use.
- New regression test `test_review_defaults_to_repo_memory` in `test_cli.py` pins the convention; two pre-existing bare-root assertions in the same file were rewritten to encode the fix, not the bug.
- Every review-artifact assertion in `test_review_live.py` (13 tests), `test_review_tracer.py` (15 tests), and `test_rule_glob.py` (25 tests) now resolves the expected path through the sidecar workspace instead of joining `tmp_path` directly. `test_diffscope.py` confirmed unaffected (zero diff, 24 tests still passing).
- Five documentation files (`SKILL.md` and four folder `README.md`s) updated so no reader is told review output lands at the reviewed root; added the `--root` string-identity discipline note (prepare/dispatch/consume must share one exact `--root` string, since the sidecar slug derives from it).
- `plugins/sec-overlay/CHANGELOG.md` gained a `1.61.6` entry and `plugin.json` bumped `1.61.5` → `1.61.6` (patch, fix-type, shipping-file change).
