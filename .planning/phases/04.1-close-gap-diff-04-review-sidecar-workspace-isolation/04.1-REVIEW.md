## Summary

Change under review: commit `f76432a` (DIFF-04). `run_review` in `cli.py`
now resolves its workspace through `RepoMemory.for_target(root,
runner=r)` / `memory.ensure(target=root)` instead of constructing
`Workspace(root)` directly, so review artifacts land under
`<root>/.sec-overlay/<slug>/` — the same sidecar convention `scan` and
`audit` already use — instead of inside the reviewed repo's own tracked
tree. The functional diff to `cli.py` is a minimal +6/-3 swap
(`cli.py:172-175`); the remainder of the 12-file commit is test
re-rooting, docs, changelog, and a version bump.

Verified independently, read-only, this pass:

- `git diff f76432a^..f76432a -- .../cli.py` confirms the functional
  change is exactly the `Workspace(root)` → `RepoMemory.for_target(...)`
  swap; no other logic in `run_review` changed.
- `main()`'s `scan` dispatch (`cli.py:401-420`) already calls
  `memory.ensure(target=args.target)` unconditionally, with no
  validation preceding it — the same ordering `run_review` now uses
  before `resolve_ref_sha`/`build_resolution`. This ordering is
  pre-existing precedent in the file, not something this diff
  introduced as a regression.
- `repo_slug()`'s `if res.returncode == 0 and url:` guard
  (`repo_memory.py:89`) correctly rejects the empty-`stdout`
  "success" response that the test suite's catch-all fake runners
  return for `git remote get-url origin` / `git rev-parse
  --show-toplevel`, falling back to the path-hash identity rather than
  deriving a wrong slug.
- Read `test_review_live.py`, `test_review_tracer.py`, `test_cli.py`,
  and `test_rule_glob.py` diffs and full content: every artifact-path
  assertion that used to read `tmp_path / "artifacts" / ...` or
  `Workspace(str(tmp_path))` now routes through either the new
  `_sidecar_ws(root)` helper or `RepoMemory.for_target(...).workspace`.
  No assertion was missed during the migration; the new regression
  test `test_review_defaults_to_repo_memory` additionally asserts the
  negative case (`not (target / "artifacts").exists()`).
- `build_resolution` and `render_review_prompt` still address the bare
  `root` (not the sidecar) — per the task's phase context this is
  intentional and out of scope for this fix; confirmed by reading
  `cli.py:251-258` and the rule-resolution call site, neither of which
  changed in this diff.
- Ran the full affected test suite: `70 passed` across the four
  modified test files. Ran `ruff check` and `ty check` against
  `cli.py`: both clean.
- Confirmed governance compliance: `plugin.json` version bumped,
  `plugins/sec-overlay/CHANGELOG.md` updated, and every touched
  folder's `README.md` updated in the same commit (`git diff --stat`).

No bugs, security issues, or quality defects were found in this diff.
`run_review` never calls `memory.update_status()` (unlike `scan`'s
dispatch), but `update_status()` reads the campaign `stages` dict in
`state.json`, which review mode never populates — review is
deliberately stateless with respect to the campaign stage-tracking
model documented throughout `SKILL.md`/`README.md`, so this asymmetry
reflects an intentional architectural separation, not a gap this fix
was expected to close. It is not reported as a finding.

All reviewed files meet quality standards. No issues found.
