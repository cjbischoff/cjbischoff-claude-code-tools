# Phase 04.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| reviewed repo tracked working tree → harness artifact writer | The harness writes files into a directory the developer commits from. Anything written there can reach a shared remote. This phase repairs this boundary. | Security findings, evidence snippets, rendered prompts |
| `--root` CLI argument → filesystem path construction and `git` argv | A caller-supplied path crosses into `memory_root`, `repo_slug`, and two `git -C <path>` subprocess invocations. | Caller-supplied filesystem path |
| `<root>/.sec-overlay/` → git ignore semantics | `RepoMemory.ensure` seeds a `.gitignore` in the sidecar's parent, which changes what git sees in a directory that also hosts the RULE-02 project rule layer. | Gitignore rules, project rule file status |

## Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation | Status |
|-----------|----------|-----------|----------|-------------|------------|--------|
| T-04.1-01 | Information Disclosure | `run_review` workspace root (cli.py); `report.md`, `review_ledger.json`, `coverage_manifest.json`, `runs/review_prompts/` | high | mitigate | `run_review` resolves its workspace through `RepoMemory.for_target(root, runner=r)` to the self-ignoring `<root>/.sec-overlay/<slug>/` sidecar (cli.py:175-177). The regression test `test_review_defaults_to_repo_memory` (tests/test_cli.py:250) asserts the reviewed root gains no `artifacts/` directory and no `report.md`. | closed |
| T-04.1-02 | Tampering | `RepoMemory.ensure` gitignore seeding vs the RULE-02 project rule layer at `<root>/.sec-overlay/rule.json` | low | accept | `ensure` writes the `*` gitignore only when the file is absent, and git does not untrack an already-tracked file, so a committed project rule file keeps its status. `build_resolution` still addresses the bare target root. | closed |
| T-04.1-03 | Tampering | `repo_slug`'s `git -C <target> remote get-url origin` and `rev-parse --show-toplevel` argv, fed from `--root` | low | accept | Commands are argv lists with no shell; the caller path occupies an operand slot after `-C`. The slug is sha256-derived and character-class sanitized, so it cannot traverse. `scan` and `audit` already route `--target` through the same code. | closed |
| T-04.1-04 | Denial of Service | multi-invocation review flow: `--prepare` → agent dispatch → consume | medium | mitigate | SKILL.md documents the identical-`--root` requirement (SKILL.md:95) so a prepared run is not orphaned by a differently-spelled root. Canonicalizing in code would change slug identity for every existing `scan`/`audit` workspace, which is out of scope. | closed |
| T-04.1-SC | Tampering | npm/pip/cargo installs | high | accept | Not applicable: the phase adds zero dependencies. The helpers core is stdlib-only (`dependencies = []`), the fix introduces no new import, and `RepoMemory` was already imported. No package-manager install task exists. | closed |
