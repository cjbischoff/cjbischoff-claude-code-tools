Port OCR's checklists for the seven languages, keeping their terse imperative prompt format. These are LLM prompt payloads consumed by the reviewing agent, not human documentation: do not apply an STE100 style pass, do not expand bullets into paragraphs, and do not add narrative introductions. Adapt only where sec-overlay vocabulary differs from OCR's — status words, severity names, and tool names.

Every doc covers the same five families in the same order established by `python.md`: null or nil dereference, thread safety, injection covering both XSS and SQL, resource leaks, and swallowed errors. Each family gets its concrete per-language triggers and then an explicit exclusion block naming the cases that must not be reported. The exclusions carry as much weight as the checks — they are what stops the general profile flooding a reviewer.

Use each language's real idioms rather than translated generics: nil map writes, unchecked type assertions, and goroutine capture for Go; `Optional.get` and non-thread-safe collections in shared fields for Java; loose comparison and unserialized input for PHP; `unwrap` on a fallible path and lock-order inversion for Rust; unhandled promise rejection and unsanitized `dangerouslySetInnerHTML` for the TS/JS doc; platform-type nullability crossing the Java boundary for Kotlin; force unwrap and implicitly unwrapped optionals for Swift.

No doc may instruct the agent to assign a finding status, a severity, or a receipt tier, or to skip a gate. Dispositions are decided by the mechanical gate, and a rule doc that claims that authority would contradict REV-03.

Section order is fixed by the file and must stay stable, so the prompt payload for a given path is byte-identical between runs.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03 | Tampering | rule-doc text injected as the agent's rule block | high | mitigate | Docs are prohibited from instructing the agent to set a status, severity, or receipt tier, and the prohibition is enforced by a negative grep in the acceptance criteria; the mechanical gate reads no rule text, so doc content cannot change a disposition. |
| T-03-10 | Denial of Service | `resolve_rule_doc` reading a map-referenced doc | low | mitigate | The conformance test proves every map value resolves to an existing non-empty file, so a missing doc surfaces in CI rather than as a review-time crash. |
| T-03-11 | Repudiation | orphan doc or orphan map entry | low | mitigate | The test asserts both directions of the map-to-file relationship, so a doc that was written but never wired, or a pattern pointing at nothing, fails the suite. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed; this plan ships markdown and one test file. |
</threat_model>
