<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv -> `diffscope.validate_ref` | Operator-supplied `--base` / `--head` reach a `git` argv. |
| `git --name-status` stdout -> `ChangedFile` | Tab-separated status and path text parsed into records. |
| git-reported path -> `fnmatch` / extension lookup | Path text drives an include/exclude decision. |
| Diff size -> parser | An attacker-controlled repo can present an arbitrarily large single-file diff. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `diffscope.validate_ref` | high | mitigate | Anchored allowlist pattern; leading-dash, empty-string, space, semicolon, backtick, and dollar-sign cases each carry a test. `ValueError` raised before any subprocess. The existing `--` separator stays in every git argv. |
| T-02-02 | Tampering | `diffscope.resolve_ref_sha` / call ordering | medium | mitigate | Task 1's fake runner asserts every `rev-parse` precedes the first `diff`, so the pinned-SHA invariant (D-07) is machine-checked rather than reviewed. |
| T-02-03 | Denial of Service | `file_select.partition` size cap | medium | mitigate | Strict greater-than comparison against `DEFAULT_MAX_DIFF_LINES` (5000); an oversized file is excluded as `too-large` and never parsed. Both cap boundaries tested. |
| T-02-06 | Tampering | path normalisation before matching | medium | mitigate | git's quoted non-ASCII path form is normalised to one canonical string before any glob or extension decision, so a path cannot be classified one way when quoted and another way when not. No path is opened for write. |
| T-02-07 | Spoofing | rename record path assignment | medium | mitigate | A rename record's `path` is the new path and `old_path` the old one (D-08); review runs against the new path's hunks, so a rename cannot be used to point review at a stale file. Covered by a rename test. |
| T-02-08 | Repudiation | exclusion reason vocabulary | high | mitigate | `ExcludedFile.__post_init__` rejects any reason outside the five-member enum, and a test walks every produced exclusion. A file can be excluded only with a reason a consumer already understands. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | accept | Zero installs in this plan; `dependencies = []` holds. No Package Legitimacy Audit table required because no install task exists. |
</threat_model>
