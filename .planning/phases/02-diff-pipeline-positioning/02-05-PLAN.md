<objective>
Close the loop: gate review-mode findings against the diff, enumerate every drop in both
outputs, and make an incomplete run say so through its exit code.

Purpose: the phase's promise is that a review run reports only what it actually looked at, and
that anything it dropped or could not place is on the record. This plan supplies the gate that
does the dropping, the two outputs that carry the drops, and the exit code that refuses to let
a partial run look like a clean one.

Output: review-mode position gating with a deterministic drop ledger, audit mode provably
untouched, and exit 3 on a partial seal.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent-produced findings -> review gate | Findings are model output; their claimed locations are unverified until gated. |
| Review gate -> reportable set | What crosses here is what the operator will act on. |
| Manifest seal -> CLI exit code | The exit code is what CI and the operator's shell trust. |
| Drop and decline records -> report and ledger | The only surviving evidence of what was removed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-18 | Repudiation | silent finding loss | high | mitigate | Every drop becomes a `DroppedFinding` rendered in a dedicated report section and written to `artifacts/review_ledger.json`; the markdown row count and the ledger count are asserted equal, so neither output can lose a drop the other kept. |
| T-02-19 | Spoofing | drop vs decline conflation | high | mitigate | `review_position_gate` returns drops and declines as separate lists, and a test asserts a `needs-position-review` finding appears in neither the kept nor the drop list. An unplaceable finding is never reported as out of scope. |
| T-02-20 | Tampering | audit-mode regression | high | mitigate | `findings_gate.py` shows a zero-line diff, `_line_in_range` gains no new call site (asserted against `HEAD~1`), and every pre-existing gate test passes unmodified. |
| T-02-21 | Repudiation | exit code masking an incomplete run | high | mitigate | A `partial` seal exits 3, distinct from 0 and from the exit-2 validation path, with each code asserted by its own test. A caller cannot mistake an unfinished review for a clean pass. |
| T-02-22 | Tampering | hunk-boundary off-by-one | high | mitigate | Both adjacency boundaries are asserted: first and last changed lines pass, the lines immediately before and after are dropped. An off-by-one here would either drop real findings or admit unreviewed ones. |
| T-02-23 | Information Disclosure | drop records in report | low | accept | Drop rows carry path, line, and rule id — metadata the operator already has read access to, written inside the local run root. Accepted: the detail is required to make a drop auditable. |
| T-02-12 | Denial of Service | gate cost on a large finding set | low | accept | The 5000-line diff cap from plan 02-02 bounds hunk volume before the gate runs, and the finding set is bounded by the scanners upstream. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | accept | Zero installs in this plan; `dependencies = []` holds and is asserted. No Package Legitimacy Audit table required because no install task exists. |
</threat_model>
