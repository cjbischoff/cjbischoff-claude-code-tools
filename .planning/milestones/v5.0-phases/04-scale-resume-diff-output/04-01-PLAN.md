units, a shipped finding becomes a diff-anchored comment payload written alongside
the coverage manifest, and every SARIF result carries a message-independent
fingerprint.

and SCALE-01's bundling is the mechanism that keeps a large changeset from
becoming one agent per file. Proving all three on one thin path first means an
architectural dead end costs one commit, not five.

`sarif.py`, bundle-aware focus enforcement in `review_agent.py`, the `run_review`
wiring, and the three test files that hold the contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| review agent response → Python core | A recorded `review-file` return is model-authored text; every field in it is untrusted input. |
| repo working tree → artifact | `existing_code` and the SARIF fingerprint are derived from file text read at a pinned ref. |
| artifact → downstream consumer | `review_comments.json` and `report.sarif` are read by a Result Management System or a comment-posting client outside this harness. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `review_agent.parse_review_response` | high | mitigate | Bundling widens the focus rule; membership is tested against exactly the reviewing unit's paths and `Finding.file` comes from the entry's own path, so a finding cannot be attributed to a sibling file (Task 2). |
| T-04-02 | Spoofing | `sarif._sarif_fingerprint` | low | accept | A 16-hex-character truncation gives 64 bits of identity space; a collision merging two distinct findings in a Result Management System is negligible at any realistic finding count. |
| T-04-03 | Information Disclosure | `review_comments.json` | low | accept | `existing_code` reproduces source already present in the reviewed repository, and the artifact is written into the self-ignoring in-repo sidecar, so no new material is exposed. |
| T-04-04 | Repudiation | `write_review_comments` | medium | mitigate | The artifact embeds `CoverageManifest.to_dict()`, so a consumer can always tell whether the comment set came from a complete or a partial run rather than inferring completeness from the file's presence. |
| T-04-05 | Tampering | `sec_overlay.models`, `sec_overlay.evidence` | high | mitigate | Both modules are the frozen JSON contract byte-mirrored by the Go port; the acceptance criteria assert `git diff --name-only` names neither, so `side`, unit membership, and the fingerprint all live in sibling modules. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | RESEARCH.md's Package Legitimacy Audit records no external packages introduced; the acceptance criteria assert `pyproject.toml` still declares an empty dependency list, so no install task and no legitimacy checkpoint arises. |
</threat_model>
