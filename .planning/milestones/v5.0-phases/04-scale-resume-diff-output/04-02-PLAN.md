<objective>
Bound a large review run in the three places it can blow up: how many git
subprocesses run at once, how many review units are dispatched at once, and how
long one unit may take before it is recorded as failed rather than hanging.

Purpose: SCALE-02's value is that a run over a large changeset finishes with an
honest partial result instead of hanging or being killed. The bound only counts if
exceeding it produces a recorded failure, so the timeout path and the coverage
manifest's partial seal are the same mechanism.
Output: three validated CLI flags, a bounded worker pool around the two git
loops, and a timeout path that fails every member of a timed-out unit.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI arguments → Python core | The three bound values are untrusted external input controlling resource allocation. |
| Python core → git subprocesses | Pooled `subprocess.run` calls; the pool size and the per-unit deadline are the only limits on concurrent process count and wall time. |
| run outcome → coverage manifest | The manifest's seal is the run's honesty record; a lost failure becomes a false claim of complete coverage. |
