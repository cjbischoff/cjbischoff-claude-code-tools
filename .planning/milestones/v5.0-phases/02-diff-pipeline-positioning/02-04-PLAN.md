<objective>
Build the never-guess positioning ladder and make every decline visible in both outputs.

Purpose: this is the phase's identity. A finding that cannot be placed with certainty must
decline, and a decline must be impossible to miss. The ladder's value comes entirely from
where it stops — an implementation that reaches for an approximate match to avoid declining
inverts the requirement.

Output: `positioning.py` at full ladder behavior, plus the markdown section and JSON ledger
that carry declines into both outputs.
</objective>

- Rung 1: a snippet matching exactly one location inside a hunk of the claimed path returns
  `exact` with that line.
- Rung 1 with the claimed line already inside a hunk and the snippet matching at that line
  returns `exact` at the claimed line.
- Rung 1 with the snippet matching two locations inside hunks of the claimed path returns
  `needs-position-review` with reason `ambiguous-multiple-matches`.
- Rung 2: no hunk match but exactly one whole-file match in the claimed path returns
  `relocated` with that line and reason `whole-file-match`.
- Rung 2 with two whole-file matches in the claimed path returns `needs-position-review` with
  reason `ambiguous-multiple-matches`.
- Rung 3: no match in the claimed path but exactly one match across exactly one other changed
  file returns `relocated` with that file's path and line and reason `cross-file-match`.
- Rung 3 with matches in two different changed files returns `needs-position-review` with
  reason `cross-file-ambiguous`.
- Rung 4: no match anywhere returns `needs-position-review` with reason `no-hunk-match`.
- An absent or empty snippet returns `needs-position-review` with reason `no-snippet` without
  attempting any rung.
- A claimed path absent from both hunk and file-text mappings returns
  `needs-position-review` rather than raising.
- The rungs are attempted in order: a case where rung 1 would succeed and rung 2 would give a
  different line asserts that rung 1's answer wins.
- Calling `resolve_position` twice with identical arguments returns equal results.
  </behavior>
  <action>
Implement `resolve_position(claimed_path, claimed_line, snippet, hunks_by_path,
file_text_by_path)` as an ordered ladder that stops at the first rung producing exactly one
match, and declines whenever a rung produces more than one:

Rung 0 — an absent or whitespace-only snippet declines immediately with `no-snippet`. There is
nothing to verify a claimed line against, and accepting the claimed line unverified is a guess.

Rung 1 — search only the lines inside the claimed path's hunks. One match returns `exact`.
Two or more decline with `ambiguous-multiple-matches`.

Rung 2 — search the whole claimed file. One match returns `relocated` with reason
`whole-file-match`. Two or more decline with `ambiguous-multiple-matches`.

Rung 3 — search every other changed file. Exactly one match in exactly one file returns
`relocated` with reason `cross-file-match`. Matches in more than one file, or more than one
match within a single other file, decline with `cross-file-ambiguous`.

Rung 4 — no match anywhere declines with `no-hunk-match`.

Every path through the function returns a `PositionResult`; a missing key in either mapping is
treated as no content to search, not an error. Record the original claim in `claimed_path` and
`claimed_line` on every result including the declines, because D-13's report section shows the
claim, and a decline that discarded the claim could not be rendered.

Do not add a fifth rung, a match-quality score, a nearest-line fallback, or a proximity window.
Each of those converts a decline into a guess, which is the one outcome this module exists to
make impossible.

Extend `tests/test_positioning.py` with every behavior above, including the rung-order case.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent-claimed finding location -> `resolve_position` | The claimed path, line, and snippet are model output, not verified fact. |
| Repo file content -> matcher | File text read to confirm or refute a claim. |
| Snippet text -> markdown renderer | Snippet content reaches a markdown table cell. |
| Review ledger -> external reader | The ledger is the machine-readable record of every decline. |
