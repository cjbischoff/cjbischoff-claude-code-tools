2. **Explicit-path staging only.** Every `git add` names the files. Never `git add -A`, `git add .`,
   or `git commit -a`. Never `--no-verify` — the prek hook is the check, not an obstacle.

   plan are `docs` type, so the plugin version increment is **patch** (D-16).

   — and needs no root `README.md`/`CHANGELOG.md`. Shipping files include `SKILL.md` and everything
   under `skills/`, folder `README.md` files included.

   that `README.md` staged in the same commit: `helpers/tests/*` requires
   `helpers/tests/README.md`; `SKILL.md` requires `skills/sec-overlay/README.md`.
6. **Repo-level commit routing.** Task 2 stages paths outside `plugins/`, so it requires **both**
   root `README.md` and root `CHANGELOG.md` staged in that same commit.
7. **Executable logic ships with a test in the same change.** The new doc guard is that test, and it
   is proven RED against the unfixed docs before the fix is applied (Task 1's verify sequence).
8. **Sanitization (D-09).** Nothing committed may contain a path below the audited target
   repository's root, a code excerpt from it, or a finding body. This plan touches only this
   repository's own files, so the boundary is satisfied by construction — re-read Task 2's ledger row
   before staging anyway.
